## Project Overview
Monorepo combining the Garmin tennis tracker app (MatchMind) and the Training Hub web dashboard, connected via Supabase. The goal is to keep developing both apps independently while integrating them through Supabase: the Garmin app records match data on-watch and syncs it to Supabase; the Training Hub web app reads that data and displays tennis stats alongside all other training data.

## Apps

### Training Hub (`apps/training-hub/`)
- Single-file HTML/JS/CSS web app (~7000+ lines in `index.html`)
- Deployed via GitHub Pages
- Multi-sport training dashboard: Gym · Climbing · Rehab · Planner · Tennis
- **Tennis tab LIVE (2026-06-12):** end-to-end pipeline verified — watch records match → syncs to Supabase `matches` → Tennis tab displays history, win rate, recent form, per-match stats
- Main file: `index.html`
- Live at: https://fpv64ncs5p-maker.github.io/Tennis-Tracker-Hub/

- Monkey C app for Garmin watches (tested on Vivoactive 6)
- Branded as **MatchMind** (app files named TennisTracker)
- Tracks live tennis matches on-watch, syncs to Supabase after each match

Root cause: `DOMContentLoaded` called `DB.saveORMCache({})` → `DB.set` → bumped `_local_modified` to *now* before `_sbInit` compared timestamps → **every device uploaded on every open**, "cloud wins if newer" never fired. Supabase Free has no backups; recovery = cloud `last_modified` reset to 1 so Jo's phone re-uploads. **Jo chose option B (safe sync, no per-record merge).** Now:
  - `saveORMCache` writes localStorage directly (derived data, not in `DATA_KEYS`) — never counts as a change.
  - Per-device keys (never uploaded): `_sync_dirty` ('1' = unsynced changes, set by `_markLocalChange()` in `DB.set`/`pushToCloud`), `_cloud_seen` (cloud `last_modified` this device last downloaded/uploaded), `_sync_force` (Restore Backup → next startup uploads as-is), `_sync_backup` (`{savedAt,data}`).
  - Uploads are a **compare-and-swap**: `PATCH user_data?id=eq.jo&last_modified=eq.<_cloud_seen>` (anon UPDATE policy exists). 0 rows → cloud moved on → `'conflict'` → `_resolveConflict()` downloads the cloud copy and keeps this device's unsynced data in `_sync_backup` (Home → Data shows **Restore it / Discard**). New ts = `max(now, _cloud_seen+1)` (clock-skew safe).
  - `_sbInit`: force flag → upload · no `_cloud_seen` yet (first run on a device) → compare cloud ts with `_BOOT_LOCAL_TS` (captured at script start, before startup writes) · cloud ts ≠ seen → download (backup if dirty) · else dirty → upload. Uploads before `_syncReady` are held back; `_sbInit` uploads afterwards if dirty.
  - Manual **☁️ Push to Cloud** (`pushToCloud(true)`) asks on conflict: OK = overwrite, Cancel = download. Tennis saves call `pushToCloud()` → conflict downloads. `online` event uploads only if dirty.
